# 日志与排障

## 日志位置

| 内容 | 位置 |
| --- | --- |
| 结构化运行日志 | `~/.omnigate/omnigate.log`（`log.path` 可改） |
| 请求元数据 | 管理台 **请求日志**，落 `request_log` / `request_attempt` |
| 请求/响应正文 | 仅在开启内容捕获后落 `content_log` |
| 上游错误体 | 请求日志的 `error_body`，截断至 2KB |

前台运行时可以 `--log stdout` 只输出到终端。需要更细的流式/协议调试时，按 [调试模式](../development/调试模式) 临时打开调试开关。

## 常见错误

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `401 missing_auth` | 请求没带 `Authorization` | 加 `Authorization: Bearer vk-...` |
| `401 invalid virtual key` | 密钥错误或已删除 | 在管理台核对或重新发一张 |
| `403 key_disabled` | 虚拟密钥被停用 | 启用密钥 |
| `402 budget_exceeded` | 日/月额度用满 | 提额、重置预算，或等窗口滚动 |
| `429 rate_limit_exceeded` | 小时请求数超限 | 提高 `rph_limit` 或降低调用频率 |
| `429 concurrency_exceeded` | 并发超限 | 提高 `concurrency_limit` 或排队 |
| `404 model not found` | `model` 不是路由别名，也不是合法 `provider/model` | 检查路由配置 |
| `all_backends_unavailable` | 路由所有目标都不可用 | 看路由健康状态、上游密钥与熔断 |
| 上游 5xx / 超时 | 上游故障或网络问题 | 看 `error_body` 与请求尝试明细 |

## 模型不可用怎么查

1. **路由页**看目标健康状态：正常 / 部分禁用 / 限流冷却 / 不可用
2. 进入 **配置中心 → 模型 → 测试密钥**，逐密钥探测，返回每把 key 的成功/耗时/错误
3. 看请求日志里的 `request_attempt`：每次 hop 用了哪个模型、哪把 key、什么状态码
4. 如果是全部密钥 `perm_banned`，手动解禁或等待定时探测自动解禁

熔断规则见 [熔断与恢复](../design/熔断与恢复)，自动解禁见 [定时探测与自动解禁](../design/定时探测与自动解禁)。

## 统计里出现「未选中模型」

逻辑路由在选出任何模型之前就失败（例如全部目标不可用、进程中断），请求没有落点模型，统计里会显示一行「未选中模型」并带上路由名。

这不是统计错误，而是告诉你「这条路由在选模型阶段就失败了」。按上面的步骤检查该路由的目标与密钥。

## 清理与保留

- 请求日志、内容日志各有保留天数，`0` 表示请求日志永久保留
- 设置页的「危险操作」可以立即按保留期清理，或清空统计
- 清空统计不会删除内容日志；清空日志不会删除每日聚合

## 健康检查

`GET /api/health` 返回模型熔断态、密钥状态与冷却倒计时，适合接入外部监控。需要管理台鉴权。

## 性能问题

| 现象 | 排查方向 |
| --- | --- |
| 首字慢 | 提供商首字超时、上游负载、代理链路 |
| 流式中途断开 | 运行设置里的流式空闲超时、反向代理读超时 |
| 统计延迟高 | 数据库大小、保留期、聚合表是否可用 |
| 内存上涨 | 并发上限、长流式连接、内容捕获量 |
