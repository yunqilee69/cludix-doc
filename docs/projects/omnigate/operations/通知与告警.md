# 通知与告警

OmniGate 有两条提醒通道：外发通知（Webhook / 飞书 / 钉钉 / 企业微信 / Slack）和站内通知中心。它们只负责提醒，不改变请求是否放行。

## 配额告警

虚拟密钥的日限额、月限额是硬限，超限返回 402。告警是叠加在上面的软提醒：

- 默认阈值 80%，可按密钥用 `warn_threshold_pct` 覆盖
- 任一窗口跨过阈值，或用满额度时推送一次
- 阈值与额度通常只上升，达到新档位才再次推送；改配额或阈值会重新武装
- 全局阈值上调时，继承全局值的密钥也会重新武装

关闭 `quota.alert_enabled` 后，站内与外发一起停。

## 通知渠道

在管理台设置页维护，支持：

| 类型 | 说明 |
| --- | --- |
| 通用 Webhook | 自定义 JSON |
| 飞书 | 机器人 Webhook |
| 钉钉 | 机器人 Webhook |
| 企业微信 | 群机器人 |
| Slack | Incoming Webhook |

每个渠道可以单独测试。测试未保存的草稿只返回结果；测试已保存的渠道会把最近一次结果写回渠道行。

**停机中断的投递不算失败**：正常重启时，进行中的投递直接返回，不写渠道结果、也不记 `quota.delivery_failed`，避免每次重启都留下假告警。

## 站内通知中心

顶栏铃铛 + 未读角标，抽屉内查看、标记、删除。

| 事件 | 说明 |
| --- | --- |
| `model.disabled` | 某模型的绑定密钥全部被禁用 |
| `model.recovered` | 模型从 `disabled` 真正恢复到 `active` |
| `quota.warn` | 虚拟密钥跨过告警阈值 |
| `quota.exceeded` | 虚拟密钥用满日/月额度 |
| `quota.delivery_failed` | 外发渠道投递失败 |

模型类通知受 `notify.model_health_enabled` 管；配额类受 `quota.alert_enabled` 管。

### 谁能看到

- `vk:<id>`：只给这把密钥的门户和管理台
- `model:<id>`：只给白名单路由实际用得到该模型的密钥；不限路由等于全部路由
- `channel:*` 等其余类型：只给管理台

已读状态按受众分开：一把密钥标已读，不会把管理台或其他密钥的同一条标掉。

### 去重与保留

- 去重状态存在被监控实体自己身上（`virtual_key.notified_level`、`model.notified_status`），删掉通知不会让它复活
- 通知表按 500 条保留，每小时清理一次；已读与未读分开计数，避免较早的未读被较新的已读挤出窗口

## 模型健康

模型级 `disabled` 是派生结论：熔断粒度是 模型×密钥，模型不可用 = 绑定密钥全部永久禁用。

因此只在 `disabled → active` 这个真正恢复的跃迁上记通知。`disabled → cooldown/no_key` 只是换了一种不可用，不算恢复。

绑定关系按 `key.ProviderID == model.ProviderID` 过滤，与路由选择同口径；跨提供商的 `model_key` 行不参与。
