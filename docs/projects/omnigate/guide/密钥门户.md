# 密钥门户

管理员在管理台创建虚拟密钥后，把密钥交给使用者。使用者访问 `/portal`，用这把密钥登录，只能查看自己的信息，全站没有写入口。

## 登录

打开 `http://127.0.0.1:17777/portal`，填入 `vk-...`。密钥保存在浏览器 `localStorage`，失效或被停用后会自动回到登录页。

密钥原文就是唯一凭据，不需要再单独建账号。

## 能看到什么

| 页面 | 内容 |
| --- | --- |
| 仪表盘 | 自己的调用次数、成功率、token、费用、延迟趋势，以及配额使用情况 |
| 模型广场 | 授权范围内可调用的路由与模型；卡片上有加权价格、流量占比、近 30 天用量 |
| MCP | 可调用的 MCP 路由与工具清单 |
| 请求日志 | 自己的请求记录与错误信息 |

### 模型广场

路由目标按权重折算成一个加权平均价格展示；权重全为 0 时按等权处理。计费模式不一致时只在占主导的模式内加权，并标注「混合计费」。

点开卡片可以看到：

- 用到的提供商与模型
- 自己的用量
- `curl` 示例
- **一键测试**：真实调用 `/v1`，与复制 curl 手跑同一条链路

一键测试会计入用量，也会被小时请求数、并发和额度拦截。示例里刻意把 `max_tokens` 设得很小，避免点一下就被扣掉一整段长回答。

### MCP 页

只列出 `endpoint=mcp` 的路由。卡片与详情弹窗复用模型广场那一套；MCP 路由没有物理模型目标，所以详情里不画「提供商占比」。

### 请求日志

日志不返回上游密钥身份（密钥名、脱敏值都不返回），但保留上游错误内容 `error_body`——调用方在失败响应里本来就看得到。

## 权限边界

- 只看得到 `allowed_routes` 允许的逻辑路由；受限密钥看不到 `provider/model` 直达 id
- 只能看到发给自己的通知，以及自己能用的模型相关的通知
- **不能**标记已读、删除通知，也不能修改任何配置
- 门户不挂限流与配额中间件：即使 `/v1` 已经超额，仍然能登录查看自己的用量和配额

## 常见问题

**登录后提示「配置异常」**：密钥的 `allowed_routes` 解析失败。这不是「不限路由」，而是该密钥的全部逻辑路由都会被 `/v1` 拒绝，需要管理员修正配置。

**看不到某个模型**：该密钥配置了授权路由，而目标路由不在白名单里。

**一键测试返回 402 / 429**：额度或限流已到上限。门户本身仍可打开，`/v1` 调用会被拦截。
