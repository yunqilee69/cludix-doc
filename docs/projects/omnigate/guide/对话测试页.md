# 对话测试页

管理台内置 Playground，用来在发凭证之前验证「模型 + 参数 + 工具」是否可用。

## 面板

| 面板 | 用途 |
| --- | --- |
| 对话 | 流式 Markdown 渲染，思考过程放在可折叠面板里 |
| Embedding | 输入文本，看向量维度和返回结构 |
| Rerank | 输入 query 与候选文档，看排序结果 |
| 生图 | 输入提示词，看图片返回 |

对话面板挂上 MCP 路由后，会把该路由暴露的工具注入模型，模型可以自动发起工具调用；工具调用过程与结果会显示在对话流里。MCP 路由的配置见 [多模态与 MCP](./多模态与MCP)。

## 测试的是真实链路

测试页发出的请求与客户端调用走同一条代理链路：同样经过路由选择、密钥权重、熔断、失败转移和统计。区别只是它用管理台自己的选择器指定模型/路由，不经过虚拟密钥。

因此：

- 测试成功的模型，客户端大概率也能用
- 测试失败时，路由页的熔断状态、请求日志里的 `error_body` 都能帮助定位
- 生图、语音、视频等测试可能会产生真实费用

## 和门户一键测试的区别

| | 对话测试页 | 门户一键测试 |
| --- | --- | --- |
| 使用凭证 | 管理台会话 | 虚拟密钥 |
| 计入虚拟密钥用量 | 否 | 是 |
| 会被限流/额度拦截 | 否 | 是 |
| 用途 | 管理员验证上游与参数 | 使用者验证自己的凭证与权限 |
